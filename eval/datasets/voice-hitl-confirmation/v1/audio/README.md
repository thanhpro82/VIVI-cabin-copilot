# HITL voice-confirmation WER corpus (issue #198)

`manifest.jsonl` currently holds a **synthetic** first pass: 90 entries (10
confirmation phrases x 9 FPT Voice Maker voices) generated by
`scripts/generate_voice_hitl_fpt_audio.py`, each tagged `speaker_code: "std_<voice>"`
and `noise_condition: "synthetic-tts"`. See
`eval/results/voice-hitl-wer/20260819T134023.754822Z/` for that run.

**This does not satisfy issue #198's WER gate.** Per the wake-word FPT
generator's own precedent (`docs/wake_word_fpt_dataset.md` on
`feature/vivi-browser-wake-word`), synthetic voices are useful for a directional
signal only — the gate requires real human speech. `RECORDING_CHECKLIST.md`
lists the same 10 phrases for a human recording pass; real recordings replace
or add to entries here, matched by a fresh `audio_id`, following the same
schema below, with no code changes to `scripts/eval_voice_hitl_wer.py`.

Each line is one JSON object per WAV file with these required fields:

```json
{"audio_id":"hitl-01-real-spk01","path":"hitl-01-real-spk01.wav","reference_text":"Đồng ý","speaker_code":"spk-01","region":"north","noise_condition":"cabin-idle","duration_ms":900,"consent_scope":"internal-poc-evaluation"}
```

Rules:

- `path` is relative to this directory and must resolve to an existing WAV file.
- `reference_text` must match one of the 10 phrases in `RECORDING_CHECKLIST.md`
  verbatim (Vietnamese diacritics included) — `word_error_rate`/`char_error_rate`
  and `src.agents.voice_intent.doc_y_dinh_phe_duyet` both diff against it.
- Audio must be 16kHz mono WAV (`src/services/voice.py`'s hard constraint).
- `speaker_code` must be pseudonymous; do not store names or contact information.
- `consent_scope` must explicitly permit the intended benchmark and demo usage.
- Keep Vietnamese diacritics in `reference_text`; WER/CER normalizes Unicode NFC
  but does not transliterate or strip accents.
- Do not commit raw audio unless the team's repository policy and consent permit it.
